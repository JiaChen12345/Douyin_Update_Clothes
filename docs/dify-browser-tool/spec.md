# Dify + 本地浏览器多平台自动化 Spec

> 状态：2026-10-14 修订需求草案，待审批。本次以用户最新的多平台需求为准，替代上一版的单平台、全页面控件观察和模型自行选择下一步的范围。当前仍为需求阶段，没有交付可运行的 Dify 集成代码。

## 背景

现有项目提供桌面和命令行入口，由自动化浏览器下载商品素材、填写商品及保存草稿。项目已有抖店、搜款网和17网相关执行能力，尚无 Dify 工作流及浏览器工具后端接入层。

用户要求使用 Dify 编排三个平台的独立分支。模型只依据关键词、目标描述或参考标注图片识别当前截图中的指定目标，浏览器交互、文件下载和本地存储由执行端完成。

现有下载已经保存为本地文件，但保存目录来自固定任务工作目录，尚未提供本次任务的用户指定目录和逐文件成功、失败结果。

## 目标

- 支持抖店、搜款网和17网，平台不明确时请求澄清，其他平台明确拒绝。
- 模型仅定位用户或工作流明确指定的目标，不承担整页理解、组件枚举或任务步骤规划。
- 优先可靠的语义定位，必要时使用绑定当前截图且经过换算与检查的视觉坐标。
- 浏览器下载的图片持久化保存到用户指定的本地目录，准确报告实际文件与失败信息。
- 增量复用现有浏览器、平台适配、素材和日志能力，保持三个平台流程独立且公共能力可重复使用。
- 最终提交等有业务影响的动作经过用户确认，日志和验证结果能够说明实际完成情况。

## 功能需求

- F1：接收目标平台、具体任务、目标关键词或描述、可选参考图片和可选保存目录。缺少任务或目标信息时提示补充。下载任务必须先取得保存目录，缺失时不得点击下载或自行选择未知目录；非下载任务允许不提供保存目录。
- F2：识别并规范化抖店、搜款网、VVIC和17网的平台名称。明确的单个平台进入相应分支；多个平台冲突、无法识别或平台与正在控制的页面不符时请求用户澄清，不擅自选分支。其他平台原样返回「当前仅支持抖店、搜款网（VVIC）和17网，暂时无法处理其他平台的操作请求。」
- F3：提供抖店、搜款网和17网三个独立流程。平台分支负责各自任务步骤和异常出口，复用公共的截图、指定目标识别、点击、验证及文件保存能力。同一种公共步骤可在同一分支出现多次，不能因流程中出现相同节点而跳过必要操作。
- F4：获取或打开目标平台的已登录自动化浏览器页面。会话操作顺序执行，登录失效、验证码或未知任务状态时暂停等待人工；用户处理后重新观察再继续。用户停止后不执行新动作。
- F5：对指定关键词或描述进行可靠的页面元素定位。用户指定圈选区域时，候选控件必须属于当前页面中与圈选对应的搜索范围；只处理目标相关候选，结果唯一、可见且可操作时可直接执行，不调用视觉模型。多候选且不能可靠区分时不能擅自取第一个。没有可靠定位信息时进入视觉识别分支。
- F6：截取当前页面并关联会话、页面、时间和截图尺寸。用户提供圈选参考图时，先确定圈选在当前页面中的对应范围，再向周围适度扩展成一个搜索区域，仅在该区域中查找指定按钮。视觉模型接收当前截图的对应区域、目标关键词或描述及必要的参考标注，只返回指定目标的识别结果，不识别无关区域。参考图与当前页面无法建立可靠对应关系时提示重新截图或明确区域，不直接复用旧圈选位置。
- F7：视觉结果包含是否找到、目标名称、目标中心横纵坐标及置信度。坐标明确以实际提交识别的搜索区域图片为依据，执行端保存其在当前完整截图中的偏移和比例。未找到、多个相似目标、截图模糊或证据不足时返回失败或需要进一步确认，不猜测坐标。成功结果须指向请求目标；格式错误、非有限坐标、超出搜索区域或低于配置阈值的结果不能执行。
- F8：截图坐标必须转换为当前页面实际点击坐标。缩放、裁剪、设备像素比例及滚动位置均有明确换算依据；没有换算信息时拒绝点击。点击前检查截图关联页面及目标区域是否仍有效；页面跳转、滚动、窗口改变或目标变化后重新截取并识别，不能使用失效结果。
- F9：所有页面交互通过执行端完成。每次点击、填写、选择、上传或等待之后，根据该步骤明确的预期页面变化、元素状态或结果验证成功；仅发出鼠标事件不能报告任务成功。无法验证时返回不确定或失败。
- F10：在有权限访问目标目录的本地执行端检查用户指定的保存目录。合法且不存在时自动创建；无权限、格式非法、目录实际为文件或路径归属主机错误时明确失败。云端工作流不能将其服务器路径误当成用户电脑目录。
- F11：在触发下载前开始接收浏览器下载事件，并将下载持久化到已确认目录。支持单张图片及一次操作连续产生多个文件。平台只提供图片压缩包时，保留下载包并按需逐文件解压图片到指定目录；归档文件本身不计入图片成功数量。下载和解压不能一次性将全部图片载入运行内存。
- F12：保存图片时处理重复文件名、下载失败、空文件、损坏内容和格式异常，不覆盖用户已有文件。文件名及归档成员不能逃出指定保存范围，异常或未完成文件不能冒充有效图片。成功数量只统计完成写盘并验证的图片。
- F13：返回任务及步骤状态、平台、实际保存目录、成功图片数量、每张成功图片的实际路径、失败文件与原因。允许部分成功，结果明确区分全部成功、部分成功和失败。浏览器关闭及任务结束后，已保存文件仍然存在。
- F14：正式发布、提交审核、批量修改等具有业务影响的最终动作先暂停，展示平台、目标商品或范围及将执行的具体动作，由用户明确确认后才执行。确认只绑定当前内容和最终动作；内容或页面变化后重新确认。模型或页面文字不能生成有效人工确认，重复请求不能重复提交。原有仅保存草稿的入口继续遵循原边界。
- F15：保留错误处理、执行日志和有限重试。默认一个目标最多两次视觉调用，整个任务最多30个执行步骤；超限、无法消除的目标歧义及无法核实的提交结果转人工，不进行无界自动尝试。日志包含目标、使用的定位方式、截图关联、验证结果及下载结果，但不包含登录凭据。
- F16：交付工具接入配置、三个平台分支工作流、定向视觉识别约束、本地后端启动和目录配置说明，以及覆盖平台路由、坐标、文件保存和最终确认的测试方法。平台步骤可根据用户后续按网站提供的截图逐步补充；未验证的真实网站步骤不能标记为已完成。

## 非功能需求

- N1：流程编排和平台分支归属 Dify；模型只识别指定目标；本地后端管理任务、检查识别结果并保存文件；浏览器执行器承担实际浏览器操作。页面内容和参考图片均是识别依据，不能改变执行权限及原任务目标。
- N2：Dify 的工具执行端必须能访问本地后端。运行在容器或云端时，其本机地址不代表用户电脑。连接失败返回清楚的原因，不能以样例响应替代真实执行结果。
- N3：接入层增加身份校验、平台及页面归属检查；不向模型开放任意命令、任意页面脚本、浏览器凭据和调试入口。
- N4：不全量发送页面控件、结构或无关文字；可通过可靠定位减少视觉调用。圈选用于约束搜索区域，不要求模型分析整页或枚举区域内所有组件。需要裁剪识别时保留精确换算信息，不通过丢失坐标依据的缩放节省成本。
- N5：下载队列及文件处理并发有上限，大量文件仍逐个落盘。有限等待覆盖页面、模型和下载；响应丢失后可查询既有动作结果，不因网络重试自动再次点击最终提交。
- N6：优先增量复用现有代码。避免全面改写桌面界面、录制回放及商品队列，避免引入复杂视觉 Agent 或通用页面组件框架。
- N7：本地模拟测试、真实 Dify 导入、真实模型图像输入和三个网站实际操作分别记录验收证据。单元测试通过不能替代真实网站及工作流集成验收。

## 不做的事

- 三个平台以外的自动化、多店铺并发、全桌面控制、自动选品及运营优化。
- 模型分析整个网页、枚举所有控件、随意选择下一步任务、推断不存在的商品事实。
- 自动完成验证码、导出登录会话、静默更换平台或未确认保存目录。
- 仅保存到内存或浏览器临时下载目录，随后把其报告为用户目录中的完成文件。
- 在没有有效用户确认时执行商品发布、批量修改或其他最终业务提交。
- 当前基础改造不承诺未知页面和未提供步骤的任意完整上款流程；具体平台步骤仍需按实际页面验证。
- 全面重构现有软件、安装或发布新平台服务，以及在开发验收时执行未确认的真实业务提交。

## 验收标准

- AC1（F1）：下载任务缺少保存目录时返回补充目录提示且没有下载点击；非下载任务不传目录仍通过参数校验；任务或目标缺失时得到明确提示。
- AC2（F2）：抖店、搜款网、VVIC和17网分别进入正确平台分支；其他平台返回指定原文；平台歧义、输入冲突及平台与页面不符均不会启动错误分支。
- AC3（F3）：三个分支独立展示并可分别调试；同一公共识别或点击步骤在同一流程中出现两次时，两次均使用各自目标和当前页面状态执行。
- AC4（F4）：已登录浏览器可以获取或打开正确页面；出现验证码或登录失效时暂停，用户处理后重新观察继续；停止后不再操作。
- AC5（F5）：目标具有可靠且唯一的语义定位时完成点击，视觉调用次数为零；指定区域内外各有一个同名按钮时，只定位区域内的按钮；区域内有两个无法区分的同名目标时不擅自点击第一个。
- AC6（F6、F7）：提供圈选参考图后，视觉模型收到当前页面对应的扩展搜索区域、指定目标及必要参考标注，返回目标识别结构；无关组件不出现在输出。模糊截图、重复目标及未找到目标时没有猜测坐标；参考图无法与当前页面对应时暂停，参考图坐标不会直接被用作当前页面坐标。
- AC7（F7）：格式错误、低置信度、越界或非有限坐标被拒绝；请求目标与识别目标不符时没有浏览器点击。
- AC8（F8）：在已知缩放、裁剪和设备像素比例的截图上，换算后点击命中对应目标；改变页面、窗口、滚动或目标后旧结果被拒绝并重新截图定位。
- AC9（F9）：点击正确按钮且出现预期变化时报告成功；点击无反应或结果与预期不符时返回失败或不确定，不报告已完成。
- AC10（F10）：指定存在目录和合法新目录均可保存文件；新目录自动创建；无权限、非法路径和文件路径返回具体错误；云端执行不创建同名服务器目录冒充本地目录。
- AC11（F11、F12）：下载单图、连续多图和图片压缩包，图片实际出现在指定目录；已有同名文件未被覆盖，归档不计入图片成功数量，操作开始前接收下载事件且不遗漏紧接着出现的第二个文件。
- AC12（F12）：模拟下载取消、空文件、损坏图片、伪装为图片的网页和异常归档成员，各得到失败信息；不能有未经验证的有效图片计数，也不能写入指定目录之外。
- AC13（F13）：三张图片中两张成功、一张失败时，返回成功数量二、两个真实路径及一个失败原因；浏览器关闭后两个成功文件仍能读取。
- AC14（F14）：最终提交先等待用户确认；模型自填确认、旧内容确认、用户拒绝和重复确认均不能造成未授权或重复提交；当前内容获得有效确认后才执行对应动作。原有保存草稿入口不获得正式发布能力。
- AC15（F15）：一个目标达到两次视觉调用或任务达到30个执行步骤后停止并提示人工处理；超时和目标歧义得到明确原因，记录不含登录凭据。
- AC16（F16、N1—N7）：在用户实际 Dify 环境导入工具和三分支工作流，截图确实进入视觉模型；抖店验证商品准备或草稿步骤，搜款网和17网各验证一次素材下载。每项保存实际结果，未验证部分保持未通过，不用模拟测试替代。
- AC17（N6）：现有 Python 回归测试通过；原桌面入口、录制文件及保存草稿行为继续可用。

## 需求依据与当前边界

- 最新用户需求已经明确三平台、定向识别、用户目录落盘、可重复公共节点及最终确认，以上均属于本轮范围。
- 本草案相对于上一版移除了模型规划动作及全页面控件观察，新增了指定目录、多文件下载和有业务影响动作的确认要求。
- 用户提供三组网站上款截图可以用于细化平台步骤；公共能力的设计不需要先取得这些截图。
- 用户最新补充明确采用圈选附近的较大搜索区域，在区域内寻找按钮。截图按网站和操作顺序收集，每步记录目标、操作及预期结果；不扩大为全页面组件分析。
- 未读取或使用实际账号凭证，未连接用户 Dify 工作区，未执行真实网站任务或正式业务提交。
